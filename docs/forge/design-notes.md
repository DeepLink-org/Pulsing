# 设计笔记 — Super-agent 架构对齐

> 来源: DeepSeek Harness 团队《Super-agent 设计探索: 迈向更自主的 Agent 系统》(2026-11)。
> 本文记录吸收进 Forge 的设计、验证过的同构、以及有意搁置的方向。

## 相互验证: 两套系统独立踩出同一组结论

| Super-agent 概念 | Forge 对应物 | 双方实证 |
|---|---|---|
| 双层架构(Router 轻模型 + Worker 重模型) | Orchestrator(纯代码) + shop 隔离回合 | 他们: 提示词委派不可靠(中性提示 5 次运行 0 次委派, p95 29.5min); 我们: judge 收稿自审 30 封不派单 → 机器代发群审。**协调必须结构化, 不能靠提示词** |
| Router 批处理(积压 Trigger 合并一次推理) | 调度器去抖(2s 静默窗攒批) | 他们量化: 单决定分摊推理 6.4s→1.6s; 我们: 30 店扇入风暴从烧穿回合预算到一次攒批处理 |
| Worker 上下文隔离、不对人类说话 | 店级 ephemeral context + silent 信 | 同构 |
| Watchdog(外部 Control Loop) | 停滞踢 + 进度看门狗(本次新增) | 他们: "进程活着≠任务推进"; 我们: ACK 乒乓 53 封客套信烧 900 秒 |
| "Session 是实现细节不是认知负担" | "给我一个 API key, 一万个 agent" | 同一产品哲学 |

## 本次吸收的三个原语

### 1. 进度看门狗 (`forge-core::watchdog`)
确定性 Fast Path 版 Control Loop: 每次轮询扫账本尾部 40 封,
- **同构循环**: 同 (from,to) 上 48 字符指纹相同的信 ≥3 封 → 诊断踢
- **杂信风暴**: 单店非协议前缀信 ≥6 封 → 诊断踢
踢信是教学式的(告诉模型错在哪、唯一正确动作是什么), 每店每类 60s 限频(幂等)。
实测可捕获: ACK 乒乓(taxonomy #4)、judge 自审、复读行为。
未做: 模型版 Slow Path(语义级"无实质进展"判断) — 留待需要时加。

### 2. 信件序号 + pulsing_recall (`Letter.seq`, 第 5 个 MCP 工具)
Inline & Spill / 链式召回的邮政版:
- journal 追加时分配单调 `seq`(跨进程回放接续)
- 回合提示中每封信带 `[信#N]`, 超过 400 字符截断并提示 recall
- `pulsing_recall(letter_id=N)` 从账本取全文 — **账本即登记处**原则的自然延伸
窗口内放摘要(Spill 引用), 模型按需召回(Chain of Recall), 不浪费上下文窗口。

### 3. 提示词兜底改写(ACK 禁令)
回合提示的兜底指令从"若未指定动作则发送结果"改为
"若未指定动作且无需处理, 直接结束回合且不发送任何信件"。
原措辞在实测中教唆出 53 封'已收到触发信'乒乓(taxonomy #4 复发)。

## 下一批候选(记录, 未实施)

- **Thread 订阅直通**: 把 review 的机器代发群审泛化为一等公民"栏目"(mailing list):
  hub 维护 `栏目→订阅店`, 编排器点火时建订阅, 迭代信件程序直通不再经编排器注入。
  他们实测直通省 37% Router token。改动面: 场景 schema + hub 路由, 属中期架构收敛。
- **投机执行**: 闸门收齐前预注入"先准备 X"(verifier 先算/写手预写修正), 有价值交付无价值丢弃。
- **存算分离 + BYOM**: Agent Loop 常驻 + 执行环境留在本机(端侧轻 daemon),
  与 forge-core::Ring 一致性哈希分片天然衔接 — "一万个 agent"的产品形态。
- **看门狗 Slow Path**: 便宜模型读账本增量判断"实质进展/方向漂移"。
