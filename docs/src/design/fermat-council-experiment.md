# 20 agent 费马证明协作议会：实验设计

**状态：方案已有一次人工授权实测，未通过全部阶段验收。**
结果及偏差见[纯内存邮箱实测](fermat-council-results.md)。
配置在 `examples/python/fermat_council.json`，它是设计清单，不是自动执行器。
这里按约 20 个智能体的规模理解需求，不是 20 层递归。
费马大定理已有证明；实验尝试协作重建并审查证明链，不把说服力、投票或
“全员同意”当作新证明。

## 1. 要检验什么

相对于上一轮自由聊天，本轮增加角色分工、组内论证、跨组接口、临时争议小组、
独立证据审计及可追踪仲裁。目标是检验：

1. 多组能否给出可组合的论证，而非各自重复一个 Wiles/Ribet 故事。
2. 缺失条件、错误接口与循环依赖能否被不同角色发现、修正并留下证据。
3. 仲裁是否受证据约束，能否保留未决问题，而非强行收敛。
4. Actor 日志能否完整回放消息、处理过程和角色绑定，不依赖邮箱数据库。

主要数学目标：排除假想本原反例，连接指数归约、小指数结论、Frey 曲线、
半稳定模性、适当的 Ribet 降层结论及级 2 处矛盾。
允许明确引用已证明的深定理；不要求在十分钟内重证模性提升。
若有人提出新路线，须另建 claim 分支并接受同样审查，不能混成已验证结论。

## 2. 精确 20 个角色

两套 Codex，每套 **1 个根 agent + 9 个 subagent**，共 20 个逻辑 agent。
不再是“20 个子 agent 外加 2 个协调器”的 22 身份方案。

| 位置 | 角色 | 人数 | 职责 |
|---|---|---:|---|
| Codex A 根 | C0 协调者 | 1 | 阶段、依赖、组建临时小组、合并报告；不裁决自己的论点 |
| Codex B 根 | J0 仲裁者 | 1 | 依据邮件证据裁决争议，记录适用范围与异议 |
| A 子组 G1 | 指数归约与小指数 | 4 | 组长、提案者、怀疑者、核验者 |
| A 子组 G2 | Frey 曲线与局部性质 | 4 | 组长、提案者、怀疑者、核验者 |
| B 子组 G3 | 剩余表示与 Ribet 降层 | 4 | 组长、提案者、怀疑者、核验者 |
| B 子组 G4 | 模性与证明依赖 | 4 | 组长、提案者、怀疑者、核验者 |
| A 子 agent | X0 独立证据审计者 | 1 | 定理来源、版本、前提与结论，不替作者补条件 |
| B 子 agent | V0 证明图核验者 | 1 | 依赖 DAG、版本、未决前提与因果引用 |

实验角色是 operator/harness 分配的语义角色，不是模型自报权限。
启动后冻结 `role → native threadId → mailbox → instance` 清单并记录其 hash；
J0 的裁决只有来自绑定的 J0 邮箱才被当作裁决，其他人同名消息只是提议。
Codex 原生工具仅用于启动、唤醒和等待，不搬运数学讨论正文。

## 3. 600 秒流程

外部控制器从启动时记单调时钟，600 秒统一停止推理，不能等“全员准备好”才重新计时。
首版同机双实例；扩展多机需记录时钟同步误差，不能用墙钟排序冒充全局因果顺序。

| 秒数 | 阶段 | 输出 |
|---|---|---|
| 0–45 | 注册与授权 | 20 个邮箱、冻结角色清单、目标及允许引用的定理包 |
| 45–165 | 四组并行 | 各组有前提/结论/证据的 claim packet，至少一轮组内反驳 |
| 165–300 | 跨组讨论 | 各组向至少两组提出接口质疑，并回应外部质疑 |
| 300–420 | 动态争议小组 | 根据实际争议临时组成作者、反对者、独立核验者三方小组 |
| 420–525 | 组合与审计 | C0 合并版本化证明图；X0 查证据；V0 查循环与未决前提 |
| 525–570 | 仲裁与一次申诉 | J0 逐 issue 给出理由；允许新证据支持的一次申诉 |
| 570–600 | 封存 | 不开新数学话题，提交最终立场、未完成任务和裁决账本 |

临时小组只复用现有 20 人，不新增模型；每人最多同时参加两个小组。
组内可全连接，组间可以直接联系任何人，不强制固定 Axx/Bxx 配对，
组长和 C0 都不是消息中转站。任意人可以引入第三方证据、指出仲裁错误、
保留理由充分的分歧。

600 秒时仍未完成的工作原样列出，不伪造 finish。停止后的离线导出和回放不调用模型，
不属于延长讨论。协调器必须保持伴生节点运行到截止，不能提早退出使本组失联。

## 4. 输入包与论证接口

控制器只向参试 agent 提供授权角色、公开定理包和候选论点，不提供预期裁决。
定理包应有可查来源与版本：小指数经典结果、半稳定模性、适当的降层命题、
以及 S₂(Γ₀(2)) 为零的论证。来源不明的模型记忆标成“待核对”，不能伪造引文页码。

各组输出必须分开写：

- G1：正整数和本原性、指数归约到奇素数或 4；p=3、n=4 的证据分别是什么。
- G2：假想反例如何产生非奇异曲线；何种模型、判别式、2 处规范化及半稳定性结论。
- G3：作用于哪个剩余表示；不可约性及局部前提；降层输出的权、级、特征与对象类别。
- G4：引用何种模性定理、如何验证适用；不能把“具有模性”写成“曲线本身就是模曲线”。

精确的专用组合推论可以作为黑箱，但必须能辨认其来源、假设和结论。
既有定理的引用不自动使证明不完整；未核对适用条件的概要也不能自动升级为完整证明。
缺少可信的小指数输入时，只能报告相应范围的条件推导，而不是无条件宣布解决全部 FLT。

## 5. 消息与证据协议

沿用 mailbox envelope 的 sender、recipient、thread_id、in_reply_to、idempotency_key。
正文建议为 JSON，业务类型为 claim/challenge/evidence/revision/panel/group_report/
proof_map/arbitration/appeal/final：

```json
{
  "experiment_id": "fermat-council-v1-run-...",
  "phase": "cross_group",
  "kind": "challenge",
  "claim_id": "G2-C3-v1",
  "issue_id": "I-07",
  "assumptions": ["p>=5", "primitive positive hypothetical counterexample"],
  "statement": "The stated implication needs an additional applicability check.",
  "evidence_message_ids": ["..."],
  "requested_action": "State the exact theorem and verify its hypotheses.",
  "confidence": 0.8,
  "supersedes": null
}
```

新观点用新 claim 版本及 supersedes 引用，不能覆盖旧邮件。争议小组各自有独立
thread_id，例如 `run/issue/I-07`；组内、全体议题也分线程，避免全部塞进一个噪声频道。
每封逻辑发送稳定幂等；读信不代表接受，领取后短时处理并完成；不得囤积大量 claim。
建议租约 90 秒，不能把整个 10 分钟实验当成一封长期领取的任务。
570 秒以后不再开启新工作；不足以安全完成的领取应保持未领取并列入尾账。

每人最多 16 封实质讨论消息；没有新信息不发感谢/确认风暴。
空箱检查间隔至少约 10 秒；同伴有新反驳时可继续，不能靠忙轮询填满实验。
证据标准优先于音量和措辞自信；说服他人必须能指向导致修订的实际邮件 ID。

## 6. 仲裁、申诉与反群体思维对照

J0 的每条裁决必须列 issue、争议双方、双方证据 ID、判定及未核验条件：

- accepted：在明确的允许输入下成立；
- conditional：仍依赖未验证的输入；
- rejected：有具体逻辑错误或反例；
- unresolved：在期限内证据不足。

不使用多数票、角色权威、消息数量或“大家都被说服”替代论证。
仲裁者不是数学真值 oracle；错误裁决也应被 X0/V0 和后续离线评价指出。

预注册三个负对照和一个正对照，仅作为 **未验证候选论点**投递，例如：

1. “仅由三数两两互素就可推出素数 p 不整除 abc”——负对照。
2. “半稳定性一句话就足以让任意曲线降层到 2”——负对照。
3. “与目标等价的引理一律是循环论证”——负对照。
4. “有独立证明、接口匹配的黑箱可以作为推导输入”——正对照。

标签、随机安排和预期依据只由 operator 控制器持有，截止后才写入 sealed-control
报告；不把答案放进参试提示词、工作区或邮件。若把本设计全文提供给参试者，
就不能再称为盲测。输入隔离也不等于对同机恶意 agent 的访问安全边界。
不能将对照中的弱断言反例误称为费马方程反例。

## 7. Actor 日志与可回放结果

邮箱状态只在 RAM 中。每节点 actor 日志记录 mailbox/directory 的生命周期、
角色绑定、投递全文、读/领取/完成变更、幂等重试、收据与拒绝。
每个生命周期独立 stream_id + sequence；重启会产生新流而不是恢复旧消息。

保存这些工件：

1. 授权、角色清单及其 hash；实际 native IDs、mailbox 和实例映射。
2. 两份 `mail-events.jsonl`，以及可选但本实验要求启用的 MCP request/response 审计。
3. 20 个线程的客户端可见对话与工具事件，凭据脱敏，内部推理/隐藏系统提示不导出。
4. 版本化 proof-dag、issue ledger、裁决和申诉、最终立场及未完成工作清单。
5. 截止后公开的对照标签、指标、文件 SHA-256 清单。

离线验收：

```bash
python -m pulsing.mailbox replay node-a/mail-events.jsonl node-b/mail-events.jsonl \
  --format json --output replay.json
```

回放只能重建日志所观察到的历史，不恢复运行邮箱、不重做工具、不唤醒模型。
序号缺失、截断或冲突事件必须显露为不完整；不能据此声称丢失的对话已经完成。
跨节点因果关系用 message ID / in_reply_to / claim 证据图核对，不只靠时间戳。

## 8. 预注册验收，不能只报“消息很多”

**协作与系统指标**

- 实际 20 个角色均绑定到不同 native 线程；每角色发送/接收及处理事件可追踪。
- 四组都有组内异议、跨至少两组的挑战及外部回应，不退化成四个孤立摘要。
- 记录动态小组、双向通信边、跨组比例、等待时间与被阻塞的依赖。
- 所有新投递可对应 actor 接受事件；领取/完成尝试、拒绝及截止时未完成均不隐藏。
- 600 秒外部截止、退出与日志完整性可核对，不继续推理来补齐结果。

**论证指标**

- 每个被接受的最终 claim 有明确前提、来源与推理边，图无循环，未决前提仍标明。
- 三个负对照识别率、正对照误拒率；J0 的正确性由独立依据评估，而非由 J0 自评。
- 立场变化能引用对方证据，保留分歧有具体理由；不能只搜索“我被说服”来计分。
- 最终分类为“输入定理下的推导”“仍有缺口的证明路线”或“未完成”，不冒称新证明。

伴生进程故障将导致该节点内存丢失，实验应标为中断，不从日志偷恢复后继续当成同一
无故障实验。若要重跑，需新的 run ID 和显式授权；读取本方案或配置不会启动模型。
